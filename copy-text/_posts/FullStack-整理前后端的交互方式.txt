## HTTP

单次 **请求-响应**，无长连接。

```mermaid
sequenceDiagram
    autonumber
    participant B as 浏览器
    participant S as FastAPI<br/>(Uvicorn)

    B->>S: HTTP GET /api/data
    Note over B,S: fetch() 发起；连接可随响应关闭或由连接复用池管理
    S-->>B: 200 application/json<br/>{"msg":"hello"}
    Note over B,S: 一次往返完成；典型 CRUD / API 调用
```

## WebSocket

先 **升级协议** 建立全双工通道，之后在**同一连接**上多次收发。

```mermaid
sequenceDiagram
    autonumber
    participant B as 浏览器
    participant S as FastAPI<br/>WebSocket 端点

    B->>S: HTTP Upgrade → WebSocket<br/>GET /ws
    S-->>B: 101 Switching Protocols<br/>accept()
    Note over B,S: 连接保持打开

    loop 会话期内可重复任意次
        B->>S: 文本帧（如 "hello"）
        S-->>B: 文本帧（如 "echo: hello"）
    end

    B--xS: 关闭连接（或异常断开）
    Note over B,S: 双向随时可发；适合聊天、协作、游戏状态
```

## SSE

浏览器用 **EventSource** 发起 **GET**，服务端在**同一响应体**里持续写入 `text/event-stream` 分帧。

```mermaid
sequenceDiagram
    autonumber
    participant B as 浏览器<br/>EventSource
    participant S as FastAPI<br/>StreamingResponse

    B->>S: HTTP GET /stream
    activate S
    Note over S: 响应不立刻结束；media_type = text/event-stream

    loop 流式推送（示例中多次）
        S-->>B: SSE 帧：data: 0\n\n …
        Note over B: onmessage 触发
    end

    S-->>B: 流结束，连接关闭
    deactivate S
    Note over B,S: 仅服务端→客户端推送；若要上行需另用 fetch/WS
```

## 轮询 Polling

多次独立的 **HTTP 请求**，模拟「刷新感」。

```mermaid
sequenceDiagram
    autonumber
    participant B as 浏览器<br/>setInterval
    participant S as FastAPI

    loop 每 3 秒（示例）
        B->>S: HTTP GET /api/status
        S-->>B: 200 JSON（uptime、tick 等）
    end

    Note over B,S: 每次都是新请求；简单但有空转与延迟权衡
```

## 长轮询 Polling

单次 HTTP **长时间占用**，服务端在「有数据或超时」后才返回；客户端拿到结果后**立刻再发起**下一次。

```mermaid
sequenceDiagram
    autonumber
    participant B as 浏览器
    participant S as FastAPI<br/>/poll

    B->>S: GET /poll?since=0
    activate S
    Note over S: 在内存中等待条件满足<br/>（新 seq 或超时）
    S-->>B: 200 JSON（可能数秒～数十秒后才返回）
    deactivate S

    B->>S: GET /poll?since=上次seq
    activate S
    Note over S: 再次挂起等待…
    S-->>B: 200 JSON
    deactivate S

    Note over B,S: 仍是「一问一答」，但「问」会等很久；不能替代真双向实时
```

## GraphQL

语义上仍是 **HTTP 请求-响应**，但路径常为 **`POST /graphql`**，**要哪些字段**写在 body 的 `query` 里。

```mermaid
sequenceDiagram
    autonumber
    participant B as 浏览器
    participant S as Strawberry<br/>GraphQLRouter

    B->>S: POST /graphql<br/>Body: {"query":"{ user { name } }"}
    Note over S: 解析 query → 执行 resolver → 组装 data/errors
    S-->>B: 200 JSON<br/>{"data":{"user":{"name":"Ada"}}}

    Note over B,S: 一个 URL；不同客户端可带不同 query；适合大型前端取数
```

## gRPC

**浏览器页面**若用本仓库里的 FastAPI，仅用于静态说明；**真正 gRPC** 在独立进程里，客户端多为**命令行或其它服务**。

```mermaid
sequenceDiagram
    autonumber
    participant C as grpc_client.py<br/>（或其它服务）
    participant G as grpc_server.py<br/>:50051

    C->>G: SayHello(HelloRequest)<br/>HTTP/2 + Protobuf 帧
    Note over C,G: 非本仓库 HTML 默认路径；需 grpc 库 / 生成代码

    G-->>C: HelloReply(message=...)

    Note over C,G: 高性能、强类型；前端若要调用需 gRPC-Web 或网关转 HTTP
```

**说明页（可选）**与典型 HTTP 静态资源相同：

```mermaid
sequenceDiagram
    participant B as 浏览器
    participant H as FastAPI<br/>07_grpc 静态页

    B->>H: GET /
    H-->>B: 200 text/html（说明文档）
```

## 表单提交

**无 JavaScript** 也可：表单 **POST** 后浏览器**整页**进入新文档。

```mermaid
sequenceDiagram

    participant S as FastAPI

    B->>S: POST /submit<br/>Content-Type: application/x-www-form-urlencoded<br/>body: username=...
    Note over S: Form(...) 解析字段
    S-->>B: 200 text/html（结果页）
    Note over B: 地址栏可能变为 /submit；页面刷新/导航
```
